# LifeCommit 🌱

스마트폰 사용을 개발자의 **Git 커밋**처럼 자동으로 쌓아 주는 개인 기록 앱(Android)입니다.
어떤 앱을 언제 얼마나 썼는지가 커밋으로 쌓이고, 잔디(Contribution Graph)와 Git 그래프로 보여 줍니다.

- **오늘(TODAY)**: 하루 요약(사용 시간, 상위 앱, 가장 오래 쓴 앱)과 라이프 그래프. 커밋을 누르면 자세한 내용을 볼 수 있고, 아래 "오늘의 한 줄"로 메모 커밋을 남깁니다. 오른쪽 아래 **+** 버튼으로 직접 커밋을 추가할 수도 있습니다.
- **WEEK / MONTH / YEAR**: 기간별 가장 많이 쓴 앱과 브랜치 통계 (MONTH / YEAR는 잔디도 표시)
- **앱 분류(브랜치)**: 앱을 web·media·sns·game·work·life·etc·system 브랜치로 나눕니다. 처음 보는 앱은 오늘 화면 아래 "분류 안 된 앱"에서 고르고, 이미 분류한 앱은 **설정(⚙) → 앱 분류**에서 바꿉니다. 바꾸면 과거 기록까지 함께 바뀝니다.
- **기록 조회**: 상단 **돋보기(🔍)** 버튼으로 기간·시간대·종류·대상·측정 방식을 골라 지난 기록을 조회합니다(공개 빌드·확장판 공통, 기기 안에서만 계산).
- **터미널**: 상단 `>_` 버튼. `git log`, `git search <키워드>` 같은 명령으로 기록을 조회합니다(`help`로 전체 명령 확인).
- **설정(⚙)**: 노이즈 필터, 앱 분류, 장소·연락처 태그(확장판만), JSON 백업 내보내기·복원, 권한 상태, 매일 21시 무렵 앱 열기 알림 켜기·끄기

## 🔒 개인정보 — 먼저 읽어 주세요

- **인터넷 권한이 없습니다.** 공개 빌드(oss)는 `INTERNET` 권한을 선언하지 않습니다. 기록은 기기 밖으로 나가지 않습니다.
- 기록은 기기 안 SQLite에 **SQLCipher로 암호화**되어 저장됩니다. 암호화 키는 Android Keystore가 보호합니다.
- **백업 파일(JSON)은 암호화되지 않습니다.** 내보낸 백업은 직접 안전한 곳에 보관하세요.
- 화면 내용, 입력한 글자, 메시지는 읽지 않습니다. 공개 빌드는 "어떤 앱이 언제 앞에 있었는지"만 기록합니다.

### 공개 빌드(oss)가 요청하는 권한

| 권한 | 이유 |
|---|---|
| 사용 정보 접근 (`PACKAGE_USAGE_STATS`) | 앱 사용 기록을 읽는 유일한 데이터 출처(Android `UsageStatsManager`) |
| 부팅 완료 수신 (`RECEIVE_BOOT_COMPLETED`) | 재부팅 후에도 약 6시간마다 도는 수집 작업을 유지하기 위해 |
| 알림 전송 (`POST_NOTIFICATIONS`) | 매일 21:00 무렵 앱 열기 알림 — 기본 켜짐, 설정에서 끄기, 거부해도 앱 사용 가능, 오늘 열었거나 이미 보냈으면 보내지 않음, 인터넷·정확한 알람 권한 없음 |

## 📥 설치

[Releases](../../releases)에서 `LifeCommit-oss-<버전>.apk`를 받아 설치하세요. 릴리스 노트에 APK의 SHA-256과 서명 인증서 지문이 있습니다.

1. 앱을 열면 **사용 정보 접근** 권한을 켜는 화면이 나옵니다. 설정에서 LifeCommit을 허용하세요.
2. 온보딩 후 **알림 전송**(`POST_NOTIFICATIONS`) 권한을 요청합니다(매일 21:00 무렵 앱 열기 알림 — 기본 켜짐, 설정에서 끄기, 거부해도 앱 사용 가능, 오늘 열었거나 이미 보냈으면 보내지 않음, 인터넷·정확한 알람 권한 없음).
3. 권한을 켠 뒤 **화면을 한 번 껐다 켜 주세요.** 그때부터 기록이 쌓입니다(그 전까지 오늘 화면에 안내가 뜹니다). 앱은 화면이 처음 꺼지기 전까지는 기기 상태를 확실히 알 수 없어서 그 구간을 기록하지 않고 "수집 확인 불가 (수집 시작 직후)"로 표시합니다. 설치 전 사용은 가져오지 않습니다.

## ➕ LifeCommit+ (소스 빌드 전용)

공개 빌드(oss)의 앱 사용 기록에 더해, 하루의 동선과 사람과의 교류까지 함께 기록하는 확장판(같은 저장소의 `full` 빌드)입니다.

- **위치 기록 및 행정동 장소 이름 (오프라인)**: 오늘(Today) 탭에서 등록 장소나 10분 이상 머문 곳을 기기 내 경계 데이터 기반 행정동 이름으로 표시합니다.
- **통화·문자·사진 기록**: 오늘(Today) 탭 타임라인에서 수발신 통화 시간, 문자, 촬영한 사진 건수를 함께 보여 줍니다.
- **메신저 답장**: 오늘(Today) 탭 타임라인에서 접근성 서비스를 통해 감지한 메신저 답장 기록을 표시합니다.
- **이동 리플레이 (일·주·월·연)**: 일일은 오늘 화면, 주·월·연은 통계 화면(WEEK/MONTH/YEAR)의 날짜 줄 아래 "▶ 이동 리플레이" 버튼에서 행정동 경계 지도 위 애니메이션(오프라인)으로 볼 수 있습니다.
- **사람(인물) 관계도**: 통계(Stats) 탭에서 통화·문자·답장 빈도를 바탕으로 교류 관계를 그래프로 시각화합니다.
- **기록 조회 (선택형, 공개 빌드·확장판 공통)**: 상단 돋보기(🔍) 버튼으로 언제·시간대·무엇을·대상·얼마나를 선택해 통화·문자·답장·장소까지 포함하여 지난 기록을 조회할 수 있습니다(기기 내 오프라인 계산).

접근성·위치·통화·문자 등 민감한 권한을 필요로 하며 Play 프로텍트 경고가 발생할 수 있어, 사용자가 어떤 권한을 허용하는지 직접 확인하고 사용할 수 있도록 사전 빌드 APK로는 배포하지 않습니다.

## ⚠️ 알아 두실 점

- **직장 프로필·보안 폴더 앱은 수집되지 않습니다.** Android가 앱이 설치된 프로필의 기록만 주기 때문입니다.
- **수집 공백**: 절전(Doze), 기기 발열, 제조사 절전 기능(예: 삼성 "절전 앱"), 강제 종료 때는 백그라운드 수집이 늦어지거나 멈출 수 있습니다. 확인할 수 없는 구간은 오늘 화면에 **"수집 확인 불가"**와 사유로 표시됩니다. 수집이 정상이면 아무것도 표시하지 않습니다.
- **디지털 웰빙과의 차이**: 화면을 끈 채 음악만 듣는 시간처럼 앱이 화면에 떠 있지 않은 시간은 세지 않습니다. 같은 앱이 2초 안에 다시 열리면 한 세션으로 이어 붙이고, 다른 앱이 3초 안에 잠깐 떴다 사라지면 원래 앱이 계속 쓰인 것으로 봅니다.
- **기록이 어긋날 수 있는 드문 경우**
  - Android가 이미 저장한 사용 기록의 시각을 나중에 고쳐 쓰는 경우(시계 보정 등)가 있습니다. 앱은 이를 감지할 수 없어서, 드물게 같은 사용이 두 번 기록되거나 지운 기록이 다른 시각으로 다시 나타날 수 있습니다.
  - **백업 복원**은 백업이 덮는 기간 안에서 시작한 앱 사용 기록을 백업 내용으로 바꿉니다. 메모·삭제 기록·설정은 합쳐집니다. 기기가 이미 수집했지만 앱이 아직 정리하지 않은 기록은 복원 시점에 따라 남거나 사라질 수 있습니다. 앱을 오래 열지 않았다면 이 범위가 몇 시간이 될 수도 있으니, **복원하기 직전에 앱을 한 번 열어 두면** 영향이 지금 진행 중인 사용 정도로 줄어듭니다.
  - **삭제는 "삭제 기록"으로만 유지됩니다.** 백업에 어떤 기록이 없다는 것만으로는 삭제로 보지 않습니다.

## 🛠️ 소스에서 빌드하기

필요한 것: Node.js 22 이상, JDK 21, Android SDK(compileSdk 36). SDK 위치는 `ANDROID_HOME` 환경 변수나 `android/local.properties`의 `sdk.dir`로 알려 주세요. 그 밖의 환경 변수나 비밀 파일은 필요 없습니다.

```bash
git clone https://github.com/moonspam/LifeCommit.git
cd LifeCommit
npm ci
npx next build
npx cap sync android
cd android
./gradlew assembleOssRelease     # 공개 빌드 → app/build/outputs/apk/oss/release/ (서명 안 됨)
```

서명하지 않은 APK는 설치할 수 없습니다. 직접 만든 키로 서명하세요(아래 "릴리스 서명" 참고). 개발 중에는 `./gradlew assembleOssDebug`로 디버그 빌드를 만들 수 있습니다.

### 풀 버전(full)을 직접 빌드하기

`full` 빌드는 공개 배포하지 않습니다. 아래 순서대로 컴퓨터에서 직접 빌드해 폰에 설치합니다. 처음이라면 준비까지 30분~1시간쯤 걸립니다.

#### 추천: AI 코딩 도구에 맡기기

개발 환경이 낯설다면 [Claude Code](https://claude.com/claude-code)나 [Codex CLI](https://github.com/openai/codex) 같은 AI 코딩 도구에게 아래 1~3단계를 맡길 수 있습니다. 빈 폴더에서 도구를 실행하고, 폰을 USB로 연결(3단계의 USB 디버깅)한 뒤 이렇게 요청하세요.

```text
https://github.com/moonspam/LifeCommit 을 클론해서 README의 "풀 버전(full)을 직접 빌드하기"대로
LifeCommit+ 디버그 APK를 빌드하고, USB로 연결된 내 안드로이드 폰에 설치해 줘.
없는 준비물(Node 22, JDK 21, Android SDK)은 설치 전에 무엇을 설치할지 먼저 알려 주고 물어봐.
```

- 도구가 실행하려는 명령은 승인하기 전에 한 번씩 읽어 보세요. 특히 설치·삭제 명령은 확인하고 진행하세요.
- 릴리스 서명 키의 비밀번호는 AI에게 알려 주지 말고 직접 입력하세요(`keytool`은 직접 터미널에서 실행).
- 설치 후 4단계(권한 켜기)는 폰에서 직접 해야 합니다.

#### 1. 준비물 설치 (한 번만)

| 필요한 것 | macOS | Windows |
|---|---|---|
| Node.js 22 이상 | `brew install node` 또는 [nodejs.org](https://nodejs.org) | [nodejs.org](https://nodejs.org) 설치 파일 |
| JDK 21 | `brew install openjdk@21` | [Adoptium Temurin 21](https://adoptium.net) 설치 파일 |
| Android SDK | [Android Studio](https://developer.android.com/studio) 설치 → 처음 실행 시 SDK 자동 설치 | 같음 |
| Git | 기본 포함 (`git --version`) | [git-scm.com](https://git-scm.com) |

JDK와 Android Studio가 설치한 SDK 위치를 알려 주세요.

```bash
# macOS (zsh): ~/.zshrc에 추가
export JAVA_HOME="$(brew --prefix openjdk@21)/libexec/openjdk.jdk/Contents/Home"
export ANDROID_HOME=$HOME/Library/Android/sdk
export PATH=$PATH:$ANDROID_HOME/platform-tools
```

저장한 뒤 `source ~/.zshrc`를 실행하거나 새 터미널을 열고, `"$JAVA_HOME/bin/java" -version`에 21이 나오는지 확인하세요.

Windows는 Temurin 설치 화면에서 **"Set JAVA_HOME variable"**을 켜고, 시스템 환경 변수에 `ANDROID_HOME=%LOCALAPPDATA%\Android\Sdk`를 추가한 뒤 `Path`에 `%ANDROID_HOME%\platform-tools`를 넣습니다. 새 명령 창에서 `java -version`으로 확인하세요.

#### 2. 빌드

```bash
git clone https://github.com/moonspam/LifeCommit.git
cd LifeCommit
npm ci
npx next build
npx cap sync android
cd android
./gradlew assembleFullDebug      # Windows: gradlew.bat assembleFullDebug
```

완성된 APK: `android/app/build/outputs/apk/full/debug/app-full-debug.apk`

> **디버그 빌드 vs 릴리스 빌드.** 디버그 빌드는 키를 만들 필요가 없어 가장 쉽습니다. 다만 USB 디버깅으로 연결한 컴퓨터에서 앱 내부(기록 DB 포함)를 들여다볼 수 있습니다. 오래 쓸 거라면 직접 만든 키로 서명한 릴리스 빌드(`./gradlew assembleFullRelease`, 아래 "릴리스 서명")를 권장합니다. 결과물은 `.../apk/full/release/app-full-release.apk`입니다.

#### 3. 폰에 설치

둘 중 편한 방법을 고르세요.

- **USB로 설치 (권장)**: 폰에서 설정 → 휴대전화 정보 → (삼성은 소프트웨어 정보 →) **빌드 번호**를 7번 눌러 개발자 옵션을 켭니다. 설정 → 개발자 옵션 → **USB 디버깅**을 켭니다. USB로 연결해 폰에 뜨는 허용 창을 승인한 뒤 실행합니다.
  ```bash
  adb install -r app/build/outputs/apk/full/debug/app-full-debug.apk
  ```
- **파일로 설치**: APK를 폰으로 옮긴 뒤(케이블, 클라우드 등) 파일 앱에서 엽니다. "출처를 알 수 없는 앱" 설치를 허용하라는 안내가 나오면 그 앱(파일 앱 등)에 허용합니다. Play 프로텍트가 "앱 검사 권장" 창을 띄우면 "자세히"를 눌러 **"검사 없이 설치"**를 고릅니다("앱 검사"를 골라도 됩니다).

#### 4. 권한 켜기

앱을 열면 권한 목록이 나옵니다. 위에서부터 차례로 눌러 켜세요.

1. **사용 정보 접근**: 앱 사용 시간 기록
2. **접근성 서비스**: 메신저 답장, 위치 기록. **APK 파일로 설치했다면** 처음엔 회색("제한된 설정에 의해 제어됨")으로 막히고 "앱의 액세스가 거부됨" 창이 뜹니다. 정상입니다. 창을 닫고 설정 → 애플리케이션 → LifeCommit+ → 오른쪽 위 메뉴(⋮) → **"제한된 설정 허용"**을 누른 뒤(화면 잠금 확인이 나올 수 있음) 다시 접근성에서 켜면 됩니다. 이 메뉴는 한 번 막힌 뒤에야 나타납니다. USB(`adb install`)로 설치했다면 이 단계가 없습니다.
3. **알림 접근 허용**: 받은 알림과 답장 짝 맞추기
4. **배터리 최적화 제외**: 화면이 꺼져도 수집 유지
5. **위치**: 앱이 띄우는 창에서 "앱 사용 중에만 허용"
6. **위치 항상 허용 (선택)**: 설정 → 애플리케이션 → LifeCommit+ → 권한 → 위치 → **"항상 허용"**
7. **통화 기록**, **문자 메시지**, **사진**
8. **연락처 (선택)**: 번호 대신 이름 표시

필수 권한을 다 켜면 메인 화면으로 넘어갑니다. 그다음 **화면을 한 번 껐다 켜면** 기록이 시작됩니다. 몇 분 뒤 다른 앱을 쓰다 돌아오면 오늘 화면에 커밋이 보입니다.

#### 5. 업데이트

새 버전으로 올릴 때는 `git pull` 후 2~3단계를 반복합니다(`adb install -r`은 기록을 유지한 채 덮어씁니다).

- **같은 키로 서명해야 덮어 설치됩니다.** 디버그 빌드의 키는 컴퓨터마다 다릅니다(`~/.android/debug.keystore`). 다른 컴퓨터에서 빌드했거나 디버그 ↔ 릴리스를 바꾸면 설치가 거부됩니다. 이때는 앱 설정에서 **백업을 내보낸 뒤** 앱을 지우고 새로 설치해 복원하세요.
- 릴리스 키를 잃어버리면 같은 문제가 생기니 키 파일과 비밀번호를 따로 보관하세요.

#### LifeCommit+에 대해 알아 둘 점

- 앱 이름은 **LifeCommit+**(앱 ID `com.lifecommit.app.full`)라서 공개 빌드와 **나란히 설치**됩니다. 데이터도 따로 저장됩니다.
- 앱 사용 시간은 공개 빌드와 **같은 방식**(사용 정보 접근)으로 기록합니다. 여기에 더해 **위치**, **통화·문자 기록**, **사진**, **메신저 답장**을 수집합니다. 접근성 서비스는 답장 감지와 위치 기록에만 씁니다. 권한이 훨씬 넓으니 무엇을 허용하는지 이해한 뒤 사용하세요. 이런 권한 때문에 Play 프로텍트 등이 설치를 경고하거나 막을 수 있습니다.
- 풀 빌드는 `INTERNET` 권한을 선언합니다(위치 라이브러리가 함께 넣음). 앱 코드 자체는 네트워크 요청을 하지 않습니다.
- 공개 빌드의 백업을 LifeCommit+에 복원해 기록을 옮길 수 있습니다. 앱 사용 기록은 두 빌드가 같은 형식이라, 백업이 덮는 기간은 백업 내용으로 바뀝니다(위 "백업 복원"과 같음). 복원하면 노이즈 필터도 백업 쪽으로 바뀝니다.
- LifeCommit+에서 **DB 초기화 뒤 백업을 복원하면** 통화·문자·사진 기록이 두 번 남을 수 있습니다(초기화 후 다시 수집된 기록과 백업의 기록이 서로 다른 id를 가짐). 초기화 전에 지운 통화·문자·사진이 다시 나타날 수도 있습니다.
- 앱을 닫아 둔 동안에도 위치를 기록하려면 설정 → 애플리케이션 → LifeCommit+ → 권한 → 위치에서 **"항상 허용"**을 직접 고르세요. Android 11부터는 앱이 띄우는 권한 창에 이 선택지가 없습니다. 연락처 권한(선택)을 허용하면 통화·문자 기록에 이름이 표시됩니다.
- 관계도에서 번호로만 된 메신저 이름은 기본으로 숨기지만, 이름 안에 들어 있는 번호는 그대로 표시됩니다.
- **기록 조회(선택형, 기기 안에서만)**: 상단 바의 돋보기(🔍) 버튼을 누르면 터미널 패널 자리에 선택형 조회 빌더가 열려 기간(프리셋 및 직접 입력), 시간대, 종류(앱, 통화, 문자, 답장, 장소), 대상, 측정 방식(시간, 횟수, 목록)을 조합해 지난 기록을 조회할 수 있습니다. 공개 빌드(oss)와 LifeCommit+(full) 모두 지원하며, 공개 빌드에서는 수집된 앱 사용 기록을 조회할 수 있습니다. 외부 서버나 LLM 없이 순수 기기 내에서 직접 계산하므로 네트워크 통신이 없고 개인정보가 기기 밖으로 나가지 않습니다.
- 오늘 요약의 장소: 등록한 장소는 그 이름으로, 그 밖에 10분 이상 머문 곳은 **행정동 이름**(예: 부산광역시 동구 초량3동)으로 보여 줍니다. 행정동은 앱에 들어 있는 경계 데이터로 기기 안에서만 계산하며, 좌표를 밖으로 보내지 않습니다. 동 경계 근처에서는 옆 동으로 나올 수 있습니다. 위치는 가만히 있어도 몇 분마다 기록되며, 기록이 15분 넘게 끊기면(폰 꺼짐, 접근성 꺼짐 등) 머무름도 거기서 끊긴 것으로 봅니다. 장소는 위치 기록으로 **추정**한 것이라 실제 머문 곳과 다를 수 있습니다(15분 안에 잠깐 나갔다 오면 계속 머문 것으로, 150m 넘게 흔들리면 다른 곳으로 볼 수 있음). 경계 데이터를 읽지 못하면 앱을 다시 시작할 때까지 위치 기록 제목은 좌표로 남고, 요약에도 동 이름이 빠집니다.
- **LifeCommit+가 다루는 민감정보와 보관 기간**
  - 받은 알림은 답장과 짝을 맞추려고 제목·내용을 암호화된 임시 저장소에 둡니다. 최대 10분이 지난 뒤 다음 알림이 올 때 정리되므로, 마지막 알림은 다음 알림이 올 때까지 남을 수 있습니다.
  - 메신저에서 입력 중인 글은 전송할 때 답장 기록에 쓰려고 메모리에만 둡니다. 보내거나 입력창을 비우거나 서비스가 멈추면 사라지고, 기기에 저장하지 않습니다.
  - 수집한 원본(문자 본문, 답장, 좌표 등)은 기록으로 정리된 뒤 7일이 지나면, **그다음 앱을 열거나 동기화할 때 앱 DB에서 삭제**됩니다. 화면에서 기록을 지워도 원본은 그때까지 남아 있다가 지워집니다. 종류별로 가장 최근 한 건은 수집 위치 표시로 남기되 내용은 지웁니다. DB는 암호화되어 있지만, 삭제한 내용이 파일의 빈 공간에서 즉시 덮어써진다고 보장하지는 않습니다.
- **LifeCommit+는 하루에 한 번 이상 열어 주세요.** 위치와 답장은 앱을 열 때 DB로 옮겨지는데, 그 전에 기기에 모아 두는 양이 500건으로 제한됩니다. 위치가 몇 분마다 기록되므로 하루쯤 열지 않으면 오래된 위치부터 사라집니다. (앱 사용 시간은 앱을 열지 않아도 수집됩니다.)
- **Android 13 이상**에서 APK 파일로 설치하면 접근성·알림 접근 권한이 "제한된 설정"으로 막힙니다. 위 "4. 권한 켜기"의 2번처럼 앱 정보 메뉴(⋮)의 **"제한된 설정 허용"**으로 풀 수 있습니다(접근성은 Android 17 에뮬레이터에서 확인했고, 알림 접근도 Android 안내상 같은 방법으로 풉니다).
